# Your first clip

This walkthrough turns a video you already have into a captioned vertical clip, reviews it, and
exports a batch that is ready to post. Nothing here contacts a social platform. You need the `asr`
extra (see [installation](installation.md)) and a source file with video and audio.

## 1. Create a workspace

A workspace is a folder whose `out/` subfolder holds rendered clips and the review queue. Use only
letters, digits, `_` or `-` in the folder name, because exports reuse it:

```sh
WORK=~/Videos/zunara/interview-2026-10
mkdir -p "$WORK"
uv run --no-sync zunara inspect ~/Videos/interview.mp4
```

`inspect` reports duration, video dimensions/codec, whether audio is present, its codec and sample
rate. Audio fields are null for an input without audio.

## 2. Render

For the example below, choose a source at least 25 seconds long; shorter files work with shorter
intervals. Give the interval in seconds from its start. Decimals are fine; `1:05` is not.

```sh
uv run --no-sync zunara render "$WORK" 10 25 --source ~/Videos/interview.mp4 \
  --hook 'Why the demo failed' --name demo-failure
```

The first render also downloads the speech model. The result is `{"file":
".../out/demo-failure.mp4"}`, next to `out/demo-failure.ass`, the subtitles burned into it. Watch
the clip now; [rendering](rendering.md) explains layout, caption language and fixes.

## 3. Add it to the queue

Rendering doesn't touch the queue. `uv run --no-sync zunara queue "$WORK"` adds one entry for each
`.mp4` in `out/` to `out/queue.json`:

```json
[{"file": "demo-failure.mp4", "title": "", "description": "", "tags": [],
  "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa", "approved_sha256": null, "youtube_id": null, "upload_state": "pending"}]
```

The digest above only illustrates the format. Keep the actual hash generated by the command.

## 4. Write the metadata and approve

Edit `out/queue.json`. Fill in `title` (1–100 characters), `description` (up to 5,000) and,
optionally, `tags`. Don't run other Zunara commands on the workspace while you edit. Then approve
the clip by its name without `.mp4`:

```sh
uv run --no-sync zunara approve "$WORK" --only demo-failure
```

`approve` requires `--only`; name multiple reviewed clips with `--only first,second`. Approval
copies the video's current SHA-256 into `approved_sha256`. If the file's bytes change, for example
because you replace it with a re-edited version, `export` and `publish` refuse it until you approve
again. Editing the text in `queue.json` doesn't affect approval. `zunara status "$WORK"` only shows
what the file says; run `zunara queue "$WORK"` to recompute the hashes.

## 5. Export

```sh
uv run --no-sync zunara export "$WORK" --platform tiktok --only demo-failure \
  --destination ~/Videos/zunara/ready-2026-10-30
```

The command prints only a count, `{"exported": 1}`. The files are in
`DESTINATION/PLATFORM/WORKSPACE-NAME/`:

```text
ready-2026-10-30/tiktok/interview-2026-10/
├── demo-failure.mp4     byte-identical copy of the approved video
├── demo-failure.txt     title, a blank line, then the description (no tags)
└── manifest.json        [{"file": "demo-failure.mp4", "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"}]
```

- Without `--only`, every clip in the queue is exported. A single unapproved clip stops the whole
  batch before any videos are exported.
- Batch folders are never overwritten or extended, so re-exporting to the same destination fails.
  Use a new `--destination` for each batch; the default `DATA_DIR/ready` accepts one batch per
  platform/workspace basename.
- `--platform` (`tiktok`, `instagram`, `x` or `youtube`) chooses the subfolder and which
  [topic policy](../reference/workspace.md#topic-policy) applies. The files are the same for every
  platform.

Export does not post anything. Use the [multi-platform API](social-api.md), the
[direct YouTube uploader](youtube.md), or the destination platform's own upload interface. If a step fails, see
[troubleshooting](troubleshooting.md). All queue fields are in the [workspace
reference](../reference/workspace.md).
